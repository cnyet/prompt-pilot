# 前端重构计划

不是再调一轮间距和颜色。前四轮（B1-B7）做的都是**参数层**的工作：令牌、字号、圆角、动效。这次动**结构层**。

---

## 一、为什么前四轮没解决"简单"

三个原因，都有数据支撑。

**1. 每页只有一种布局形态。**
五个页面全是「居中单列 + 标题 + 一个内容块」：库 `max-w-[1180px]`、设置与模板 `max-w-[880px]`、工作台三栏 `240/1fr/320`。没有一页在版式上有变化，翻页像看同一页的不同内容。

**2. 信息块数量太少。**
设置 15 个、评估 8 个、模板 4 个。参考稿（Open Orbit）一屏有 5 个状态块 + 12 个分区卡片，信息密度是数量级的差距。

**3. 工作台把"文档"当"表单"做。**
1406 行的 `StudioWorkspace` 渲染的是 8 个可编辑 textarea 依次排列，每块带一行操作按钮。这是表单的骨架，不是文档的阅读体验。**用户来看的是提示词成品，不是填表界面。**

---

## 二、目标与衡量

不追求"更像某个站"，追求三件可测的事：

| 目标 | 衡量方式 |
|---|---|
| 版式有变化 | 五页至少三种不同的版式骨架（单列阅读 / 双栏工具 / 卡片网格） |
| 信息密度提升 | 单屏可见信息块（卡片、分区、数据点）平均从 ~9 提到 ≥ 15 |
| 文档可读 | 正文行宽 60-75 字符、行高 ≥ 1.75、每字段有明确编号与标题层级 |

不做的：换技术栈、加动效库、改信息架构、动任何业务逻辑。

---

## 三、设计系统 v2

在 B7 基础上补三个结构性能力，都是新增而非替换。

### 3.1 版式骨架

新增 `PageShell` 三种变体，页面各选其一，不再人人居中单列：

```
reading     max-w 760   单列，阅读为主（工作台文档区、评估）
workbench   三栏自适应    工具型（工作台）
grid        max-w 1280  卡片网格（库、模板）
```

### 3.2 文档排版（新增 `DocSection`）

工作台的核心不是表单，是文档。每个字段变成一节：

```
01  ─────────────────────────────────
    角色

    你是一名产品方向的资深内容编辑。
    专长：任务拆解、结构化表达与质量核验。
    视角：先确认目标与边界，再交付结果。

    [hover 时才出现：重算 / 加长 / 缩短 / 更具体]
```

- 编号用 `caption` 但字距拉开，放在标题上方
- 标题 `h3` 18px，正文 16px / 1.8
- 分隔线只出现一次（节与节之间），字段内部零边框
- 操作条默认隐藏，hover 或键盘聚焦时淡入

### 3.3 数据表达

新增 `StatTile`（数字 + 标签 + 可选趋势）与 `MeterBar`（单值进度条）。用于：库页统计、评估页胜率、设置页成本。

## 四、页面级重构

### 4.1 工作台（优先级最高）

**现状**

```
[需求卡 240] [文档 1fr] [诊断 320]
   表单堆叠，每字段一框 + 一行按钮
```

**重构后**

```
┌ 文档头 ─────────────────────────────────────────────┐
│  面向普通读者的产品周报            [保存] [导出] [⋯] │
│  8 字段 · 已存 v0 · 1000 字左右 · 离线模板           │
└──────────────────────────────────────────────────────┘
┌ 大纲 180 ┬ 正文 1fr ────────────────┬ 诊断 320 ┐
│ 01 角色  │ 01 ─────────             │ 错误 0  │
│ 02 目标  │ 角色                      │ 警告 2  │
│ 03 上下文│ 正文……                    │         │
│ …        │ 02 ─────────             │         │
└──────────┴───────────────────────────┴─────────┘
```

具体改动：

1. **需求输入折叠**：生成开始后，需求区收成一行摘要条（可点开改），把纵向空间还给文档。
2. **文档头独立**：标题、元信息、主操作从工具栏里升出来，成为页面级 header，不再挤在 tab 上方一行。
3. **左侧加大纲**：8 个字段的锚点导航，滚动时高亮当前节，点击跳转。这是"像文档"的关键。
4. **字段节化**：见 3.2，去掉每个字段的卡片感与常驻按钮行。
5. **诊断常驻右栏**：保持，但条目改为「一行结论 + 展开看理由」，默认更安静。

**为什么这能解决"简单"**：一屏内同时出现文档头、大纲、正文、诊断四层结构，且每层形态不同，不再是三个等宽盒子。

### 4.2 提示词库

**现状**：单列表格，四列，一屏一条信息。

**重构后**：卡片网格（2 列 / 1440 下 3 列），每张卡：

```
┌────────────────────────────┐
│ 面向普通读者的产品周报      │
│ 2 个版本 · 最新 v1          │
│ ─────────────────────      │
│ 需求：帮我写一篇面向普通…   │  ← 首行预览
│ 2026/11/10 13:29  AI 生成   │
└────────────────────────────┘
```

- 顶部保留统计（条数 / 版本 / 近七天）但改成 `StatTile`
- 点击卡片 → 右侧详情抽屉（现有逻辑复用），不再是表格里点「打开」
- 空态保留

### 4.3 设置

**现状**：一列长滚动，四个 `Section` 堆叠。

**重构后**：左侧锚点导航（模型 / 成本 / 数据 / 快捷键）+ 右侧分区卡片，宽度 1080。滚动到哪高亮哪。成本区顶部加三个 `StatTile` + 一张 `MeterBar`（各阶段占比）。

### 4.4 模板

**现状**：单列 6 行。

**重构后**：两列卡片，每张：图标块、名称、适用场景、一行示例输入、右下角「用它开始」。信息量翻倍且仍克制。

### 4.5 评估

**现状**：空态 + 三步说明。

**重构后**：空态保留，下方加「评估结果长什么样」的结构示意：胜率 `MeterBar`、维度条形（判定口径 / 事实性 / 结构 / 语气），数值标 `—` 表示暂无数据。**不编造数字**，只展示版式。

| 批次 | 内容 | 交付 | 预估 |
|---|---|---|---|

## 六、验收

1. 五页至少三种版式骨架，截图可辨
2. 单屏信息块 ≥ 15（P2、P3 完成后重数）
3. 对比度沿用脚本核对，浅色 ≥ 4.5:1、深色 ≥ 4.5:1
4. 390 / 768 / 1024 / 1440 无横向滚动
5. `pnpm test` 全绿（当前 478）、`tsc` 0、clean build 通过
6. 键盘可走完主流程，焦点可见

---

## 七、风险与边界

| 风险 | 处理 |
|---|---|
| 工作台改动最大，回归面广 | P2 单独提交，测试全绿才继续；保留旧三栏作为 fallback 一个批次 |
| 卡片网格在 1024 下过挤 | 网格断点 1024 单列、1280 两列、1440 三列 |
| 大纲吸顶与文档滚动冲突 | 用 `sticky` + `scroll-margin-top`，不监听 `scroll` 改状态（IntersectionObserver 只做高亮） |
| 越改越花 | 沿用 `DESIGN.md` 12 条禁令；新增组件不引入阴影与渐变 |

### 一个真实的坑

`useActiveSection` 最初放在「空闲态提前 return」之后，导致空闲到生成态之间 hook 数量变化，页面直接崩（`This page couldn't load`）。已移到所有提前 return 之前。
