# PromptPilot 设计系统与界面方案

**这份文档解释「为什么」，不记录「具体值」。** 令牌以 `app/globals.css` 为唯一真相，本文只写取向、约束与判断依据。改令牌时同步更新本文的表格，流程见第八节。

最近一次对齐实现：B5（暖色纸感）、B7（刊物尺度）、P1-P4（结构重构）。相关决策见 `docs/adr/0001`、`0002`。

---

## 一、设计简报

### 1. 功能摘要

把一句话需求扩写成结构完整、边界清晰的八字段提示词，并用真实模型试跑一次，让用户当场看到效果。

### 2. 首要用户动作

写一句话，拿到能直接用的提示词。编辑与诊断都是第二步。

### 3. 设计方向

**编辑刊物感**：暖米白纸底、纯白卡片、衬线大标题、克制的粉彩分区、大留白。

方向依据见 `docs/adr/0001-editorial-visual-direction.md`。三条核心判断：

1. 与文档并排办公的场景决定了浅色优先，不做深色优先。
2. 页面级标题用中文衬线，正文与控件保持无衬线，形成刊物式对比。
3. 层级靠字号、留白、极浅底色差建立；不靠阴影、渐变、彩色块。

### 4. 范围

五个页面：工作台、提示词库、评估、模板、设置。外加顶栏、侧栏、⌘K 命令面板。

### 5. 布局策略

工作台是唯一的三栏工具页；其余页面各自不同的骨架，不共用一套居中单列（见第三节）。

### 6. 关键状态

空态、生成中、生成完成、已被用户修改、试运行中、试运行失败、诊断有错误、离线模式。每个状态都要有明确视觉与文案，不允许"看起来没变化"。

### 7. 交互模型

输入即开始；生成不打断；用户改动立即写入文档，后到的 AI 内容降级为建议。

### 8. 内容要求

中文界面。禁止感叹号，禁止 em dash（——），禁止"强大""智能"这类空词。数字与 token 数一律等宽。

### 9. 已定论的问题

- 浅色优先（深色同等可用，但不是主场景）
- 不引入展示字体（中文子集体积不可接受），衬线走系统栈
- 不引入动效库与图标库
- 评估判定的是输出，不是提示词文本

## 二、设计令牌

### 色彩

全部使用 OKLCH。中性色带暖色相（约 70-80 度），不使用死灰。

**浅色（默认）**

| 令牌 | 值 | 用途 |
|---|---|---|
| `--bg` | `oklch(0.977 0.007 81)` | 页面底，暖米白 |
| `--bg-sunken` | `oklch(0.962 0.009 81)` | 凹陷层：代码块、输出区、统计块 |
| `--surface` | 纯白 | 卡片、面板、输入框 |
| `--surface-raised` | 纯白 | 浮层、选中项 |
| `--surface-inset` | `oklch(0.956 0.010 82)` | 只读区、需求摘要块 |
| `--border` | `oklch(0.924 0.012 80)` | 容器边框 |
| `--border-strong` | `oklch(0.878 0.014 78)` | 悬停、焦点边框 |
| `--border-subtle` | `oklch(0.949 0.009 80)` | 只用于分隔，不包裹容器 |
| `--text` | `oklch(0.211 0.005 68)` | 主文字，暖近黑 |
| `--text-muted` | `oklch(0.513 0.011 73)` | 次级文字 |
| `--text-faint` | `oklch(0.532 0.01 73)` | 元信息、占位符 |
| `--accent` | `oklch(0.55 0.13 40)` | 主操作、链接、焦点 |
| `--accent-hover` | `oklch(0.49 0.13 40)` | 悬停 |
| `--accent-subtle` | `oklch(0.955 0.026 45)` | 选中行底色 |
| `--on-accent` | 近白 | 压在 accent 上的文字色 |

**粉彩分区（只做背景，不做文字色）**

`--tint-coral` / `--tint-sage` / `--tint-lavender` / `--tint-butter`。用于诊断分组、入口方块、空态图标底、评估步骤序号。

**语义色**：`--success` `oklch(0.531 0.095 162)`、`--warning` `oklch(0.545 0.112 72)`、`--danger` `oklch(0.545 0.155 29)`、`--info` `oklch(0.5 0.07 265)`。

**为什么强调色要压深**：参考稿的亮赤陶 `#d86a47` 配白字只有 3.46:1。主色压到 5:1 以上才能承白字；亮度更高的赤陶只用于圆点、下划线这类装饰。

**深色**：底 `oklch(0.185 0.008 70)`，卡 `oklch(0.218 0.008 70)`，暖炭灰而非冷黑；`--accent` 提到 `oklch(0.72 0.12 45)`，因此 `--on-accent` 必须换成深色文字。

### 字体

```
--font-sans:  -apple-system, "PingFang SC", "Microsoft YaHei", system-ui
--font-serif: "Songti SC", "Noto Serif SC", Georgia, serif
--font-mono:  ui-monospace, "SF Mono", Menlo, Consolas
```

- **衬线只用于页面级 `h1`**。字段标题、正文、按钮、数据一律无衬线。
- 等宽只用于结构标签、变量占位符、JSON、token 数与耗时。中文正文绝不用等宽。
- 字重只用 400 / 500 / 600。数字一律 `tabular-nums`。

字号阶梯（比例约 1.2，宽屏下 display 再放大一档）：

| 档位 | 字号 | 行高 | 用途 |
|---|---|---|---|
| caption | 12px | 1.4 | 元信息、状态标签 |
| label | 13px | 1.4 | 表单、按钮、导航 |
| body | 15px | 1.7 | 默认正文 |
| body-lg | 16px | 1.75 | 文档正文、输入区 |
| h3 | 18px | 1.4 | 字段标题、面板标题 |
| h2 | 26px | 1.28 | 区块标题 |
| display | 34px（宽屏 44px） | 1.12 | 页面标题，衬线 |

大标题必须配 `text-balance`：中文在窄栏里极易掉出单字成行。

### 间距

4px 基准，刻度 2 / 4 / 6 / 8 / 12 / 16 / 20 / 24 / 32 / 40 / 56。

节奏不是处处一样：面板内元素 8-12，面板内边距 16-20，区块之间 40-48，文档字段之间 28。分隔优先用 1px `border-subtle`，而不是加大间距。

### 圆角与阴影

- 圆角：chip 6，控件 8，面板 16，浮层 16，圆点全圆。
- 阴影：**只有浮层允许**，`0 12px 32px -16px`。卡片一律不加阴影，层级靠底色与边框。

### 动效

规则见 `docs/adr/0002-css-only-motion.md`。只有两个类：

- `.rise` 120ms：内容首次出现，`opacity 0→1` 加 `translateY(6px)`
- `.reveal` 180ms：容器展开，`opacity` 加 `translateY(-4px)`

限制：只动 `opacity` 与 `transform`；`prefers-reduced-motion: reduce` 下全部归零；同一屏同类动效只出现一次，不做逐项延迟。

## 三、信息架构

```
顶栏 48px：面包屑 · ⌘K 搜索入口 · 模型状态 · 主题切换
├─ 侧栏 240px（可折叠）
│   工作台 / 提示词库 / 评估 / 模板 / 设置
└─ 内容区，按页面选骨架：
     工作台  workbench  大纲 180 / 文档 1fr / 诊断 320（<1440 退标签页）
     提示词库 grid       卡片网格 + 右侧详情抽屉
     评估    grid       空态与结果版式并排 + 三步流程
     模板    grid       两列卡片
     设置    grid       左锚点导航 + 右分区
```

五个页面**不允许共用同一种居中单列骨架**——这是上一轮"看起来简单"的结构性原因。

### 工作台三栏

| 栏 | 宽度 | 内容 |
|---|---|---|
| 左 | 180px | 文档大纲 01-08（滚动高亮、点击跳转）+ 紧凑需求摘要 |
| 中 | flex，最小 520px | 文档头 / 三视图（结构化、渲染文本、JSON）/ 字段节 |
| 右 | 320px，可折叠 | 诊断（16 条规则） |

## 四、页面规格

### 4.1 工作台

**空态**：居中单列（820px）。大标题 + 一句话说明 + 输入区 + 六个粉彩入口方块 + 「试试这些 / 你会得到」双栏（右侧列真实八字段名）。

**生成中**：八个字段按顺序流式填充，当前字段有骨架；「停止生成」常驻可点。

**生成完成**：文档头（标题、元信息、主操作）→ 三视图标签 → 八个文档节。每节 = 编号 + 标题 + 正文；**操作条（重算/加长/缩短/更具体/重新生成）默认隐藏，悬停或键盘聚焦才出现**。

**假设 chip**：一行可点 chips + 一行说明，不套外框。

**试运行**：变量表单、输出区、耗时与 token；无模型时禁用并说明原因，不伪造输出。

**诊断**：右栏常驻，按 error / warn / info 分组，每组一块粉彩底色；条目分「结论 / 原因 / 建议」三级；修复与忽略是图标按钮，悬停显形。

### 4.2 提示词库

标题 + 一行真实统计（条数 / 版本数 / 近七天更新）+ 搜索与新建。列表是**卡片网格**（1440 三列、平板两列），每张卡：标题、描述（没有描述时取最新版本正文首行，最多 90 字）、标签、版本数与更新时间。整卡可点，打开右侧详情抽屉（版本时间线 + 基于某版本继续编辑）。

### 4.3 评估

顶部是创建区：选一条提示词、按行填样本（最多 5 条）、开始评估。成功标准自动取自目标版本自身，不另填。

下方是评估记录列表，点开看详情：通过率、与 v0 的胜率、已判定样本数三个统计块；样本输出可展开对照当前版本与 v0；判定按样本分组，每条标准一个 verdict（满足 / 部分满足 / 不满足）。

**没有评委模型时标「待人工判定」**：样本输出照常保存，通过率与胜率显示 `—`，并说明原因。绝不把"没判"显示成 0 分。规则见 `docs/adr/0003-eval-judges-outputs.md`。

### 4.4 模板

两列卡片：图标块、名称、适用场景、示例输入、动作「用它开始」（暂未开放）。模板只调整字段权重与默认约束。

### 4.5 设置

左侧锚点导航（模型 / 成本 / 数据 / 快捷键），右侧分区。

**模型区**：顶部状态条（已接入真实模型 / 离线模板 + 当前模型 + 端点），下面四个字段（API Key、端点、生成模型、评估模型），每个字段带来源标签（设置 / 环境变量 / 默认值）。密钥写入本机数据库，界面只显示末四位，永不回传明文；「清除全部覆盖」回落到环境变量。错误贴在字段下方并接 `aria-describedby`。

**成本区**：四个统计块 + 按阶段与模型两张表，带 `*` 的数字表示只统计到部分调用。

## 六、关键交互细节

1. **输入即开始**：空态输入框回车触发，不需要先点按钮。
2. **中断保留**：`Esc` 或「停止」后已生成字段可编辑，未生成字段显示「未生成」加单独重试。
3. **诊断实时**：150ms 防抖刷新，不阻塞输入；点击问题滚动并选中命中文本。
4. **修复不覆盖手改**：批量修复跳过用户改过的字段；对脏字段单项修复需二次确认。
5. **错误就地化**：字段级错误贴在字段上，只有全局错误才用页面级提示。
6. **离线可作业**：断网或无密钥时编辑、诊断、导出、浏览库全部可用，只有模型相关操作禁用并说明原因。
7. **⌘K**：命令面板，五个页面 + 主题切换，方向键选、回车执行、Esc 关闭。

## 七、绝对禁止项

评审时逐条检查。三条于 B5/P3 修订，修订理由写在条目里。

1. **禁止左侧色条**（`border-left` 大于 1px 的彩色强调条）。用前置图标或严重度圆点代替。
2. **禁止渐变文字**。
3. **禁止玻璃拟态**作为默认风格。
4. **禁止大数字 + 小标签 + 辅助统计的 hero 指标模板**。统计块只在确有数据时出现，且不堆三行。
5. **禁止装饰性的等尺寸卡片网格**。〔修订〕卡片网格本身允许（库与模板在用），禁止的是**每张卡承载同样空信息**的装饰性排布；每张卡必须有自己的真实内容。
6. **禁止把模态框当第一选择**，优先内联或抽屉。
7. **禁止在按钮、标签、数据上用衬线**。衬线只给页面级 `h1`。
8. **禁止装饰性动效**，动效只传达状态。
9. **禁止纯黑**。〔修订〕卡片面允许纯白（`--surface`），因为它要与暖米白底形成清晰分层；但**正文与背景不得使用纯黑**，中性色都要带色相。
10. **禁止交互组件缺状态**（disabled / loading / error 必须有）。
11. **禁止界面文案用感叹号**，禁止"强大""智能"这类空词。
12. **禁止 em dash（——）**，用逗号、冒号或括号。

## 八、令牌变更流程

令牌是全局的，改一个值会影响两套主题与五个页面。按顺序做：

1. 改 `app/globals.css` 的 `:root` 与 `.dark` 两个块，两套主题**同时改**。
2. 跑对比度脚本（OKLCH → sRGB → WCAG），确认浅色与深色最低都不低于 4.5:1。
3. 更新本文第二节的表格。
4. 跑 `pnpm test`、`tsc`、clean build，再出 1440 / 1024 / 390 三档截图。
5. 若改动涉及方向性判断（例如换色相、换骨架），先写 ADR 再改。

**跑测试前先停掉 3100 上的应用服务**：测试与运行中的应用共用一个 SQLite 文件，会互相干扰。
