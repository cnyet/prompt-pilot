# PromptPilot 设计系统与界面方案

> 语域：**product**。设计服务于任务，不做品牌表演。判断标准不是"像不像 AI 做的"，而是**一个熟悉 Linear / Figma / Stripe 的用户坐下来会不会信任这个界面**。

## 一、设计简报

### 1. 功能摘要

PromptPilot 是一个提示词生产工作台：把一句话需求变成结构完整、边界清晰的八字段标准提示词，并能试运行、评估、对比、迭代、归档。面向三类用户：不懂提示词方法的业务人员、要把提示词固化进代码的开发者、要批量调优的提示词工程师。

### 2. 首要用户动作

**把一句话变成一份可用的提示词。** 屏幕上第一眼必须让人知道"在这儿打字"，而不是"我该点哪儿"。

### 3. 设计方向

- **色彩策略：Restrained（克制）**。中性色为底，单一强调色（深青蓝）只用于主操作、当前选中、焦点环。理由：这个界面上最需要颜色的地方是 **diff 视图**（新增绿 / 删除红）和**诊断状态**，界面装饰抢色会直接损伤核心功能可读性。整个产品最鲜艳的区域应该是 diff，这是对的。
- **主题与场景句**：白天在办公室，用户浏览器旁边开着文档和表格，正在打磨一份要交给团队复用的提示词，环境是明亮的日光和一块对比度不高的雾面屏，情绪是专注而不是探索。→ **浅色为主，深色同等可用**。浅色是默认，因为要与文档、表格并排阅读，长时间做正文校对时浅色底更省力。
- **命名锚点**：Linear（信息密度与状态精致度）、Stripe Dashboard 的表单清晰度、VS Code 的 diff 可读性。
- **刻意避开的方向**：紫色渐变 + 玻璃拟态的"AI 味"（第一层反射）；蓝白卡片式云控制台（第二层反射，因为参考站火山 PromptPilot 就是这个味道）。所以既不紫，也不火山蓝。

### 4. 范围

- 保真度：高保真，可直接进入生产实现。
- 广度：五个页面的完整界面（工作台 / 提示词库 / 评估 / 模板 / 设置），首版重点打磨工作台。
- 交互性：可交互产品，非静态稿。
- 时间意图：打磨到能发布。

### 5. 布局策略

固定左导航 + 顶栏，主区域是工作台的三栏工作区（输入与假设 / 编辑器 / 诊断与版本）。层级靠**边框与底色分层**建立，不靠阴影和卡片。工作台里没有卡片，只有面板；面板之间是 1px 边框和 4 到 8 个色阶差的中性底色。信息流从左到右：**说需求 → 看结构 → 看问题**，与用户的心智顺序一致。

### 6. 关键状态

| 状态 | 用户需要看到与感受到的 |
|---|---|
| 空态（工作台） | 一个聚焦的输入框，六个场景模板，三个示例。不要欢迎语，不要插图。用户应该 3 秒内开始打字 |
| 空态（提示词库） | 一句话说明这里会存什么，一个"去工作台"按钮 |
| 解析中（< 300ms） | 输入框下方出现两行骨架，不要转圈 |
| 澄清中 | 已取消阻塞式追问。生成完成后再出现一排假设 chip（输出语言 / 长度 / 受众 / 格式），点哪个改哪个。深度访谈是折叠在输入框下方的可选入口 |
| 流式中 | 字段逐个填充，当前字段有插入符，右下角"停止生成"。已生成内容在中断后必须保留 |
| 局部失败 | 只标记失败字段，其他字段可用，失败字段上给"重试" |
| lint 有 error | 右侧栏计数徽标变红，编辑区对应文本有下划线波浪，不是弹窗 |
| 自动试运行中 | 输出区流式打印，顶部显示耗时与 token 实时累加 |
| 断网 | 顶栏持续可见的"离线模板模式"标记，需要模型的操作禁用并说明原因 |
| 首次使用 | 用工作台空态本身完成教学，不做引导蒙层 |

### 7. 交互模型

- **输入即开始**：在空态输入框打字后回车即开始，不经过"选择模板"这类前置步骤。粘贴长文本时自动切到改进模式，输入框上方显示模式标识，可一键切换。
- **不打断**：没有任何必须回答的问题。模型替你做的决定以假设 chip 事后呈现，改哪个只重算哪个。深度访谈是折叠入口，不占主路径。
- **AI 产出永远可编辑、可回退**：每个字段、每段渲染文本都能直接改。AI 生成的内容带一个极轻的来源标记（左侧 2px 圆点，非色条），用户改动后标记消失。
- **补丁制而非覆盖制**：优化不重写全文，产出 diff 补丁，逐字段接受或拒绝。这是信任的关键机制。
- **键盘优先**：`⌘Enter` 生成或运行，`⌘K` 命令面板，`⌘S` 保存版本，`Esc` 中断流，`\` 折叠左栏。
- **中断不掉内容**：任何流式操作都能随时停，停下时已生成的部分立刻变成可编辑状态。

### 8. 内容要求

- 按钮文案：动词开头，不超过 6 字。生成 / 停止 / 试运行 / 应用修复 / 保存版本 / 全部接受。
- 错误文案三段式：**发生了什么 → 为什么 → 怎么办**。例："模型返回的内容不是合法 JSON。可能是输出被截断。已自动重试一次，你可以点这里手动重试，或把 max_tokens 调大。"
- 空态文案：一句话说明能做什么，加一个动作。
- 微文案禁止项：感叹号、"强大的"、"智能的"、"简单几步"、"一键搞定"。
- 动态内容范围：提示词正文 50 到 4000 字；变量 0 到 20 个；版本 1 到 200 个；库中提示词 0 到 5000 条；lint 问题 0 到 30 条；运行记录 0 到 10000 条。

### 9. 实现期推荐参考

`spatial-design.md`（三栏可折叠工作区）、`interaction-design.md`（字段编辑器与表单密集区）、`typography.md`（中英混排与等宽字体搭配）、`color-and-contrast.md`（diff 配色与评估色阶）、`cognitive-load.md`（右侧诊断面板的信息削减）、`motion-design.md`（流式与面板折叠的动效）。

### 10. 已定论的问题

评审时把三个悬而未决的问题定掉，避免阻塞实现：

1. **工作台落地页**：中栏是输入框空态，下方加一条"最近 3 条"次级列表。两者都要，因为首次用户与回访用户需求不同，而这条列表高度不到 100px，不干扰"在这儿打字"的第一眼判断。
2. **1280px 下右栏**：默认折叠。右栏是诊断面板，只在有问题时需要看；折起来后中栏多 300px，长提示词可读性明显更好。
3. **图表**：全部用横向条，**去掉雷达图**。六维雷达在五个维度以上难读数，而目标用户不是数据分析师。评估页用"成功标准逐条判定表"，比任何图表都清楚。

## 二、设计令牌

### 色彩（OKLCH）

所有中性色朝强调色相（205 到 215）做 0.004 到 0.008 的微量着色，避免死灰。不使用 `#000` 与 `#fff`。

**浅色主题**

| 令牌 | 值 | 用途 |
|---|---|---|
| `--bg` | `oklch(0.985 0.004 210)` | 主背景，微冷纸白 |
| `--bg-sunken` | `oklch(0.963 0.006 212)` | 代码块、输出区、凹陷容器 |
| `--surface` | `oklch(0.997 0.002 210)` | 面板、弹出层内容面 |
| `--sidebar` | `oklch(0.952 0.008 215)` | 第二中性层：左导航、工具栏 |
| `--border` | `oklch(0.900 0.006 215)` | 默认 1px 边框 |
| `--border-strong` | `oklch(0.845 0.008 215)` | 输入框、需强调的边界 |
| `--text` | `oklch(0.250 0.012 220)` | 主文字 |
| `--text-muted` | `oklch(0.500 0.012 220)` | 次级文字、标签 |
| `--text-faint` | `oklch(0.630 0.010 220)` | 占位符、元信息 |
| `--accent` | `oklch(0.520 0.090 205)` | 主操作、当前选中、焦点 |
| `--accent-hover` | `oklch(0.455 0.100 205)` | 悬停 |
| `--accent-subtle` | `oklch(0.950 0.022 205)` | 选中行底色、当前项背景 |

**语义色**

| 令牌 | 值 | 说明 |
|---|---|---|
| `--success` | `oklch(0.550 0.130 150)` | 与 accent 的青蓝色相拉开 55 度，不混淆 |
| `--warning` | `oklch(0.680 0.140 075)` | 琥珀 |
| `--danger` | `oklch(0.550 0.170 027)` | 红 |
| `--info` | `oklch(0.580 0.100 250)` | 蓝，仅用于中性提示 |

**diff 专用**（全界面最鲜艳的区域，符合功能优先级）

| 令牌 | 值 |
|---|---|
| `--diff-add-bg` | `oklch(0.960 0.032 150)` |
| `--diff-add-mark` | `oklch(0.900 0.070 150)` |
| `--diff-del-bg` | `oklch(0.960 0.026 027)` |
| `--diff-del-mark` | `oklch(0.905 0.062 027)` |

**评估色阶**（只在评估页使用，主界面不出现分数）：不用彩虹。1 到 5 分沿 accent 色相做明度与彩度递增的单调阶梯，并在低分段借用 `--warning` 与 `--danger` 的色相，使"差"在视觉上自然偏暖。分值永远同时显示数字，颜色只是辅助。

**深色主题**：`--bg` `oklch(0.185 0.008 215)`，`--surface` `oklch(0.215 0.008 215)`，`--sidebar` `oklch(0.163 0.008 215)`，`--border` `oklch(0.300 0.008 215)`，`--text` `oklch(0.930 0.005 215)`，`--text-muted` `oklch(0.700 0.008 215)`，`--accent` `oklch(0.720 0.100 205)`。深色下的 diff 用低明度底加高明度描边，不用浅色底。

### 字体

产品语域**只用一套字族**，中英混排由系统栈承担，不引入展示字体。

```
--font-sans: -apple-system, BlinkMacSystemFont, "Segoe UI", "PingFang SC",
             "Hiragino Sans GB", "Microsoft YaHei", system-ui, sans-serif;
--font-mono: ui-monospace, "SF Mono", "JetBrains Mono", Menlo, Consolas,
             "Sarasa Mono SC", monospace;
```

等宽字体**只用于**结构标签、变量占位符、JSON 视图、token 数与耗时。中文正文绝不用等宽（中文字形在等宽字体里会散架）。

| 档位 | 字号 | 行高 | 用途 |
|---|---|---|---|
| caption | 12px | 1.4 | 元信息、token 数、时间 |
| label | 13px | 1.4 | 表单标签、按钮、导航、表格 |
| body | 14px | 1.6 | 默认正文 |
| body-lg | 16px | 1.65 | 提示词编辑区正文（核心阅读区，给足尺寸） |
| h3 | 19px | 1.4 | 面板标题 |
| h2 | 23px | 1.35 | 页面标题 |
| display | 28px | 1.25 | 仅空态使用，一个页面最多一处 |

字重只用 400 / 500 / 600。层级靠字号加字重对比（比例 1.2，产品语域用紧凑比例，避免噪声）。数字一律 `font-variant-numeric: tabular-nums`。

中文正文行宽控制在 34 到 40 字（约等于 65 到 75ch）。

### 间距

4px 基准。刻度：2, 4, 6, 8, 12, 16, 20, 24, 32, 40, 56。

节奏要求（**不是处处一样**）：面板内元素 8 到 12，面板内边距 16，面板之间 1px 边框不加间距，区块之间 32 到 40，页面上下留白 24。表单同一组内 12，组之间 28。

### 圆角与阴影

- 圆角：chip 与徽标 4，按钮与输入框 6，面板 8，对话与抽屉 12，状态点与头像全圆。
- 阴影：**极少使用**。面板一律用 1px 边框加底色分层，不用阴影。只有浮层（弹出菜单、对话框、抽屉）使用 `0 8px 24px oklch(0.25 0.02 220 / 0.10)`。

### 动效

- 时长：悬停与焦点 120ms，面板折叠与标签切换 180ms，抽屉与对话框 220ms。
- 缓动：`cubic-bezier(0.16, 1, 0.3, 1)`。不用回弹与弹性曲线。
- 只动 `transform` 与 `opacity`。不动 width / height / top / left。
- 流式文字逐字出现**不加动画**，加了会晕。
- 骨架用 opacity 呼吸，周期 1.4s。
- 不做入场编排，产品是进来就干活的。

## 四、页面规格

### 4.1 工作台（重点）

**空态**：中栏垂直居中一个输入框（宽 640px，高 96px，`body-lg`），下方一行六个场景模板 chip，再下方三个可点击示例，最底部一条"最近 3 条"次级列表。没有欢迎语，没有插图，没有标题大字。

**生成中**：中栏出现八个字段骨架，按依赖顺序逐个填充。当前字段末尾有 2px 插入符。右下角浮出"停止生成"。

**假设 chip**：生成完成后，中栏顶部出现一排可点的假设 chip（输出语言 / 长度量级 / 受众 / 格式），每个带当前取值与下拉候选。点击修改后只重算受影响字段，其余字段逐字不变。未改过的 chip 用 `--text-muted`，改过的加一个极小圆点标记。

**生成完成**：中栏顶部三个标签（结构化 / 渲染文本 / JSON）。结构化视图是八个可折叠字段块，每块头部有字段名、来源标记、操作菜单（重新生成 / 加长 / 缩短 / 更具体 / 复制）。右栏只有两个标签：诊断与版本。诊断显示问题计数，按 error / warn / info 分组，每条含位置、原因、修复按钮。

**自动试运行**：变量有默认值时，生成结束后立即在中栏上方跑一次，真实输出优先展示，提示词结构退到下方。顶部一行显示模型、耗时、token、费用。变量表单在输出区左侧，枚举给下拉，长文本给多行。手动重跑与全屏查看在右上角。

**补丁审阅**：优化后中栏切换为 diff 模式，逐字段展示变更，每块右上角有"接受 / 拒绝"，顶部有"全部接受 / 全部放弃"。若目标字段用户手改过，该块标"有冲突"，默认拒绝，需显式点"覆盖"。

### 4.2 提示词库

工具条一行：搜索框（占满剩余宽度）、标签过滤、排序、新建。列表是表格，列：标题、标签、版本数、v0 胜率、更新时间、操作。首版不做卡片视图与归档状态：库在第一个月基本是空的，先建一套 CMS 不划算。

详情用右侧抽屉（宽 480px），含描述、变量清单、版本时间线（每次变更的来源、时间、胜率变化），底部导出按钮。

### 4.3 评估

任务列表：名称、模式（基线对比 / 多样本批量）、样本数、状态、创建时间。任务详情：顶部一句话结论（例如"相比 v0 胜率 4:1，主要改善在输出格式与不做什么"），中间是**成功标准逐条判定表**（每条标准一行，列为各版本，单元格为满足 / 部分满足 / 不满足），底部是样本输出原文。**不使用雷达图**，横向条与判定表已经够读。

### 4.4 模板

按场景分组（通用问答、内容创作、代码生成、数据分析、客服对话、结构化抽取）。每张模板显示名称、适用场景一句话、字段齐全度。动作是"用这个模板新建"，直接跳到工作台并预填。

### 4.5 设置

四个分区，用左侧二级导航切换：模型配置（表格加编辑表单，密钥字段只显示"已配置"，不显示明文）、评估规则（成功标准判定口径、盲评位置随机化开关、评估模型选择）、数据（导入、导出、清空、从备份恢复，清空需二次确认）、关于（版本、快捷键表）。

## 五、组件清单与状态矩阵

每个交互组件必须实现全部状态，不允许只做一半。

| 组件 | 状态要求 |
|---|---|
| Button | default / hover / focus-visible / active / disabled / loading（保持宽度不变，图标位换成旋转） / danger 变体 |
| IconButton | 同上，加 tooltip |
| Input / Textarea | default / hover / focus / disabled / readonly / error（边框变 danger 加下方提示） / 字符计数 |
| Select / Combobox | 同上加展开态、无匹配项、多选 chip |
| SegmentedControl | default / hover / selected / disabled |
| Tabs | default / hover / active（底部 2px accent 线） / disabled / 带计数徽标 |
| Chip / Tag | default / hover / selected / removable |
| FieldBlock（字段块） | collapsed / expanded / generating（骨架） / edited / failed / streaming |
| LintItem | error / warn / info / fixing（应用中） / fixed |
| DiffBlock | 行内模式 / 并排模式 / 已接受 / 已拒绝 / 有冲突（用户改过） |
| RunOutput | empty / streaming / done / failed / canceled |
| Table | default / hover 行 / selected 行 / 排序中 / 空 / 加载骨架 / 分页 |
| Drawer | 关闭 / 打开 / 拖拽调整中 / 全屏 |
| Toast | success / warning / error / info，3 秒自动消失，可手动关闭 |
| EmptyState | 图标位（可省）+ 一句话 + 一个动作 |
| 判定条 | 满足 / 部分满足 / 不满足 / 未评估 / 人工改判标记 |
| StatusDot | idle / parsing / streaming / done / error，配文字标签 |

## 六、关键交互细节

1. **输入即开始**：空态输入框回车触发解析，不需要先点按钮。输入框右下角有 `⌘Enter` 提示。
2. **澄清可跳过且必须可见**：右上有常驻"跳过"，跳过后用默认值，并在结果区顶部显示假设条。
3. **中断保留**：`Esc` 或"停止"后，已生成字段立即变可编辑，未生成字段显示"未生成"加单独重试按钮，绝不整段丢弃。
4. **lint 是实时的**：输入 150ms 防抖后刷新，不阻塞输入。点击问题项滚动到对应字段并选中。
5. **补丁审阅才落库**：接受补丁前不改动原版本。接受后生成新版本，不是就地覆盖。
6. **diff 双层**：行级背景加词级高亮。
7. **键盘全覆盖**：见下节快捷键表。
8. **离网可作业**：断网时编辑、lint、导出、浏览库全部可用，只有模型相关操作禁用并说明。
9. **错误就地化**：字段级失败标在字段上，全局失败才用 toast。

## 七、绝对禁止项

这些是本项目的硬性禁令，评审时逐条检查：

1. **禁止左侧色条**（`border-left` 大于 1px 的彩色强调条）。lint 项、通知、字段块一律改用前置图标或严重度圆点。
2. **禁止渐变文字**（`background-clip: text`）。
3. **禁止玻璃拟态**作为默认风格。
4. **禁止大数字加小标签加辅助统计的 hero 指标模板**。
5. **禁止等尺寸卡片网格**铺满页面。
6. **禁止把模态框当第一选择**，优先内联或抽屉。
7. **禁止在 UI 标签、按钮、数据上用展示字体**。
8. **禁止装饰性动效**，动效只能传达状态。
9. **禁止 `#000` 与 `#fff`**，所有中性色都要带品牌色相。
10. **禁止交互组件缺状态**（disabled、loading、error 必须有）。
11. **禁止界面文案用感叹号与"强大""智能"这类空词**。
12. **禁止 em dash（——）**，用逗号、冒号或括号。
