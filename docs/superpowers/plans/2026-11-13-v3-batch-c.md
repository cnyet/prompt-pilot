# v3 Batch C（SSE 路由与账本关联）Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 落地三个 v3 SSE 路由（`/api/generate` 首轮、`/api/records/[id]/optimize` 继续优化、`/api/records/[id]/repair` 修复）、`lib/db/records.ts` 写路径、ledger 的 recordId/iterationId 关联与 v3 stage 支持；配集成测试。

**Architecture:** 路由骨架参照 v2 `app/api/engine/generate/route.ts` 的 ReadableStream 模式（close 守卫、enqueue 守卫、abort 监听），事件换成 v3 协议（Batch B 的 `sse-v3.ts`）。流水线：创建 PromptRecord（status running）→ 发 `start` → 消费 `provider.stream()`，delta 经 MetaSplitter 切分实时下发 → 流结束解析 meta → 落迭代与记录 → `usage` + `done`。中断保留半成品（status canceled），模型失败不写半成品正文（迭代 status failed、output 空）。记录层幂等用 Batch B 的 LRU 挂在 `/api/generate` 模块级单例；迭代层靠 `requestId @unique`，撞约束时复述已有迭代（SSE 重放）而不是 500。无可用模型时返回 503 JSON（不是 SSE），文案可读中文。

**Tech Stack:** Next.js App Router Route Handler、Prisma（test.db 隔离）、zod、vitest。

**Spec:** `docs/ARCHITECTURE.md` §三（API 表）、§四（数据模型）、§五（SSE 协议）、§九（角色分配）、§十二（幂等）；`docs/ROADMAP-V3.md` §2.2、§3 Phase 1；`PRODUCT.md` FR-1.5/1.6、FR-2.5/2.7、FR-3.6、FR-4.4/4.5。

## Global Constraints

- 不修改 v2 路由（`app/api/{engine,eval,prompts,run,settings,stats}/` 既有文件，settings/stats 在 Batch D 单独扩）；不改 `lib/engine/schema.ts`、`lib/engine/sse.ts`、`lib/llm/types.ts`。
- `lib/llm/ledger.ts` 只做本计划列出的加法：LedgerStage 类型、recordId/iterationId 字段、STAGE_LABELS 三条。其余行原样。
- 用量未知为 null；usage 事件在 token 完全未知时不发（先例 `app/api/engine/generate/route.ts:681-684`）。
- 正文流必须立即 flush（不做服务端聚合缓冲）；`thinking: 'off'`；`maxTokens` 用 `8192`。
- 测试用 `MOCK_LLM_FAULT=valid` + `allowValidMock: true`（setup-env 已删真实 key），绝不打真实网关。
- 中断（`request.signal.aborted`）不算失败：保留已生成正文，迭代与记录 status = `canceled`。
- 文案禁感叹号、em dash、emoji；错误码全大写下划线（`NO_MODEL` / `RECORD_NOT_FOUND` / `ITERATION_IN_FLIGHT` / `INVALID_INPUT`）。

## Review Focus

1. **双击只产生一条记录**：同一 requestId 并发两次 `/api/generate` 只建一条 PromptRecord、一条迭代，第二个请求收到重放结果；验证 = 集成测试并发用例 + DB count 断言。
2. **失败不写半成品正文**：模型故障（`MOCK_LLM_FAULT=truncated` 等）时迭代 output 为空、status failed，记录 status failed；delta 已发内容不落库；验证 = 故障画像集成用例。
3. **中断保留正文**：abort 后迭代 output = 已收到的正文、status canceled；验证 = 集成测试 abort 用例。
4. **元数据不泄漏**：任何 SSE 事件 payload 或落库正文里不得出现 `<<<PROMPTPILOT_META>>>` 或 JSON 元数据行；验证 = 集成测试全文扫描断言。
5. **撞 requestId 唯一约束不 500**：继续优化重复 requestId 时返回 200 重放已有迭代；验证 = 集成测试重放用例。

  iterationId: string
  recordId: string
  output: string
  notes: string[]
  modelId: string | null

  tokensOut: number | null
  costCny: number | null
  latencyMs: number | null
  status: 'completed' | 'canceled'

export async function failIteration(input: { iterationId: string; recordId: string; modelId: string | null; errorCode: string | null }): Promise<void>
export async function getRecordWithIterations(recordId: string): Promise<RecordWithIterations | null>
export async function findIterationByRequestId(requestId: string): Promise<PromptIterationRow | null>

语义：
- `createRecord`：title 先取 `sourceInput.slice(0, 24)`，status `running`，iterationCount 0。requestId 只存于迭代层（记录层 LRU 在路由内做，不落库）。

- `getRecordWithIterations`：含 iterations 按 seq 升序；供 Batch D 详情与测试断言。

### Task 3: /api/generate 路由（SSE 首轮）

**Files:**
- Create: `app/api/generate/route.ts`
- Test: `tests/integration/generate-v3-route.test.ts`

**Interfaces:**
- Consumes: Batch B 全部（`buildGenerateMessages` / `buildOptimizeMessages` / `MetaSplitter` / `encodeSseEventV3` / `SSE_V3_HEADERS` / `withIdempotency` 语义的 `createIdempotencyStore`）、Task 1 ledger、Task 2 db helpers、`getGenerateProvider` / `getOptimizeProvider`（lib/llm/registry）、`getEffectiveLlmEnv`（lib/settings/store）、v2 错误映射工具（定位 `lib/llm/errors.ts` 里 kind→code 的既有函数并复用；只 import，不修改）。
- Produces: `POST /api/generate` SSE 流。

请求体（zod 校验，非法返回 400 JSON `{ code: 'INVALID_INPUT', message, retryable: false }`）：

```ts
{
  mode: 'generate' | 'optimize'
  sourceInput: string            // generate 1..2000 字；optimize 1..8000 字
  instruction?: string           // optimize 可选，1..500 字
  targetType?: 'text' | 'image' | 'video'  // 仅 generate，默认 'text'
  originTemplateId?: string
  requestId?: string             // 客户端生成的幂等键
}
```

流程（在 route handler 内）：
1. 解析与校验 body；`mode==='optimize'` 且给了 `targetType` 时忽略 targetType（记录存 'text'）。
2. `getEffectiveLlmEnv()` → provider = mode==='generate' ? getGenerateProvider(env, { allowValidMock: true }) : getOptimizeProvider(env, { allowValidMock: true })；provider 为 null → 503 JSON `{ code: 'NO_MODEL', message: '未配置可用模型，先在设置里接入模型再试。', retryable: false }`。
3. 记录层幂等：模块级 `const idempotencyStore = createIdempotencyStore<GenerateOutcome>()`；有 requestId 时用 `store.run(requestId, executor)`。executor 返回 `{ recordId, iterationId, meta, usage, status, output }`（重放时直接重发完整事件序列，见下）。
4. executor：`createRecord`（title 输入前 24 字）→ `appendIteration`（kind = mode，seq 1）→ 返回 `ReadableStream` Response（SSE_V3_HEADERS）：
   - 先发 `start { recordId, iterationId }`。
   - 消费 `provider.stream(chatRequest)`：每个 chunk 的 `delta` 喂给 `MetaSplitter.push`，返回片段立即 `enqueue` 为 `delta { text }`；`reasoningDelta` 直接丢弃；`usage` 记下（不出事件）。
   - 流结束：`body += splitter.flushTail()`；`finish()` 得 meta；meta.title 为 null 时降级 title = `sourceInput.slice(0, 24)`，notes = meta.notes（降级时为 []）。发 `meta { title, notes }`。
   - `completeIteration`（output = body，status completed；abort 时 status canceled 且 output = 已发正文）→ `recordLlmCall({ stage: mode === 'generate' ? 'generate' : 'optimize', provider, modelId, recordId, iterationId, usage, latencyMs, ttftMs, finishReason, status: succeeded/failed/canceled, ... })`（recordLlmCall 失败仅 console.warn，不阻塞）→ 发 `usage { tokensIn, tokensOut, costCny, latencyMs }`（tokens 完全未知时不发）→ 发 `done { recordId, iterationId, status: 'completed' | 'canceled' }`。
   - 模型抛错：不落半成品 → `failIteration` + recordLlmCall(status failed, errorCode) → 发 `error { code, message, retryable }`（用既有错误映射）→ 发 `done { ..., status: 'failed' }`。
   - abort：只发 `done { status: 'canceled' }`，不发 error。
5. 重放（幂等命中已完成结果）：不重建记录，直接按缓存 outcome 重发 `start → delta(output) → meta → usage → done` 事件序列；in-flight 命中时等待同一 promise 完成后同样重发。
6. 迭代层兜底：`appendIteration` 抛 P2002 时 `findIterationByRequestId` 取已有迭代 → `getRecordWithIterations` → 按其 status 构造重放序列（failed 则发 error + done(failed)）。

chatRequest 构造：

```ts
{
  modelConfigId: mode === 'generate' ? DEFAULT_GENERATE_MODEL_CONFIG_ID : DEFAULT_OPTIMIZE_MODEL_CONFIG_ID,
  messages: [{ role: 'system', content: system }, { role: 'user', content: user }],
  maxTokens: 8192,
  thinking: 'off',
}
```
