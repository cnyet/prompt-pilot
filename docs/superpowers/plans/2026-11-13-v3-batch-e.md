# v3 Batch E（studio-v3 工作台 UI）Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 把 `/studio` 从 v2 八字段工作台替换为 v3 双模式工作台：生成 / 优化输入、SSE 流式 Markdown 结果、源码与复制下载、对比原文、改动说明、继续优化、按需本地检查、收藏评分与存模板，并完成主题切换移顶栏与移动端四项底部导航。

**Architecture:** 页面只做服务端能力探测，交互集中在 `components/studio-v3/`。纯逻辑先落到可单测模块：i18n 字典、diff、R101-R108 检查、流状态 reducer、输入校验、格式化。UI 组件消费这些模块与既有 v3 API；不 import 任何 v2 引擎或 `components/studio/*`。重新生成新增 `POST /api/records/[id]/regenerate` 追加 `generate` 迭代，不新建记录。

**Tech Stack:** Next.js App Router + React 19 + TypeScript、Tailwind v4、react-markdown + remark-gfm、vitest（node 环境）。

**Spec:** `PRODUCT.md`（FR-1..FR-6、FR-10、AC-1..7、AC-19..24、AC-27）、`DESIGN.md`（Workspace Result Surface / Rating / Compare / Responsive）、`docs/shape-studio-v3.md`、`docs/ROADMAP-V3.md`（Phase 2）、`docs/ARCHITECTURE.md`（§4 SSE/API、§6 Markdown、§7 diff、§8 检查）。

## Global Constraints

- 测试隔离 `data/test.db`，绝不读写 `data/app.db`；测试在 `beforeEach` 清理 `promptRecord`、`promptIteration`、`template`、`llmCall` 与预算键。
- 未知值一律 `null` 并用「—」显示；未评分显示「未评分」；不写 0、0 星或空串代替。
- `stage` 只认 `generate | optimize | repair`；本地检查不产生 `LlmCall`。
- v3 代码不 import `components/studio/*`、`lib/engine/schema.ts`、`lib/engine/lint/*`、`lib/engine/render.ts`；v2 模块只在 Phase 6 删除。
- 不新增依赖，唯一例外是本计划批准的两个 Markdown 依赖：`react-markdown`、`remark-gfm`（CONTEXT.md 明确指定）。
- 界面文案全部进 `lib/i18n/zh.ts`，中文优先；禁感叹号、em dash（未知值「—」是唯一例外）、emoji、「强大 / 智能 / 一键起飞」。
- DESIGN 硬规则：单屏 primary 最多 1 个；金色面积 ≤10%；同屏 glow ≤2；中文最小 12px；数字 `tabular-nums`；只动 opacity/transform（glow 除外）；`prefers-reduced-motion` 下归零。
- 所有实现者串行执行（`data/test.db` 单文件）；每个任务结束跑 `pnpm run typecheck` 与自己的定向测试，提交信息用中文。
- 交互验收无自动化浏览器测试：组件逻辑必须放进纯模块并用 `tests/**/*.test.ts` 覆盖；UI 本身靠 `pnpm build` 与手动冒烟。

### Controller Rulings（与下文冲突时以此为准）

1. 批准新增 `react-markdown` 与 `remark-gfm` 两个依赖。CONTEXT.md「Markdown 渲染只用 react-markdown + remark-gfm」与 ARCHITECTURE §6 已指定；其余依赖一律不加。若判断错误，代价是移除两个依赖并换本地解析器，`MarkdownView` 与其测试重写。
2. 「重新生成」新增 `POST /api/records/[id]/regenerate`，追加一条 `stage=generate`、`kind=generate` 的迭代，不新建记录。若判断错误，代价是一条路由与一组集成测试，可单提交回滚。
3. AC-6 在 Batch E 只做结果区内的「紧凑两轮对比」；记录详情抽屉里的完整对比归 Phase 3。若判断错误，代价是少一个选择器或后续补 UI。
4. 移动端导航在 Batch E 改为四项底部标签栏；`/eval` 页面保留 URL 可达，Phase 6 再删。若判断错误，回滚 shell 两文件即可。
5. `copiedAt` 埋点本批不写：复制动作不新增 PATCH。若判断错误，成功指标「一次通过率」延迟到 Phase 3。
6. 客户端取消按服务端语义记为 `canceled`，界面显示「已中断」；不新增超时错误码。
7. 无密钥判断在服务端用与路由相同的 provider 解析（`allowValidMock: true`），只把布尔值传给客户端；`ModelStatusBanner` 仍走 v2 `/api/run`，Phase 6 处理，工作台自身状态为准。
8. R101-R108 的阈值、级别与可修复性按 Task 3 固定；后续调整只改 `lib/engine/check.ts` 与测试。

## Review Focus

1. **中断不丢正文、失败不覆盖上一轮**：停止后保留已生成文本并标记「已中断」；续写失败时结果面仍显示上一轮完整输出，不能变空。
2. **未知值与未评分**：模型、耗时、token、费用未知显示「—」；评分清除后显示「未评分」，任何位置都不出现 0 星或 ¥0.0000 冒充未知。
3. **复制与导出逐字一致**：复制 Markdown、下载 `.md`、纯文本复制分别对应源码 / 源码 / 去标记文本；Markdown 视图不得执行原始 HTML。
4. **双击与重试幂等**：同一请求进行中重复提交被忽略，只产生一条记录 / 一个迭代；失败重试用新 requestId，传输错误重试可复用同一 requestId 走重放。
5. **无密钥与并发**：无可用模型时提交禁用并给原因与设置入口，库 / 模板 / 复制 / 导出仍可用；记录 running 时继续优化、修复、重新生成都返回 409 并保持界面可恢复。
