# v3 Batch D（记录/模板/统计 API 与 seed）Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 补齐 v3 Phase 1 剩余 API：记录列表/详情/修改/删除、模板列表/创建/删除与 12 条内置模板 seed、v3 成本统计与预算聚合，并收口 Batch C final review 的 DEFER 项。

**Architecture:** 数据访问集中在 `lib/db/records.ts` 与新建的 `lib/db/templates.ts`；路由只做参数校验、错误映射与响应封装。统计在 `lib/llm/stats-v3.ts` 复用 `ledger.summarizeCalls` 的趋势与分桶，独立计算当月 KPI 与预算使用率。seed 数据与幂等 upsert 放 `prisma/seed.ts`，以 `slug` 为幂等键。所有未知值保持 `null`，不写 0。

**Tech Stack:** Next.js App Router Route Handlers、Prisma 6 + SQLite、zod 4、vitest。

**Spec:** `docs/ROADMAP-V3.md`（§2.1/§2.2/§2.6/Phase 1）、`PRODUCT.md`（FR-6/FR-7/FR-9/FR-11）、`docs/ARCHITECTURE.md`、`.superpowers/sdd/2026-11-13-v3-batch-c/progress.md`（DEFER 项）。

## Global Constraints

- 测试隔离 `data/test.db`，绝不读写 `data/app.db`；测试数据在 `beforeEach` 清理 `promptRecord`、`promptIteration`、`template`、`llmCall` 与预算键，并调用 `invalidateSettingsCache()`。
- 未知值一律 `null`：评分未评为 `null`、金额未知为 `null`、预算未设置为 `null`。零调用是已知的 0。
- `stage` 只认 `generate | optimize | repair`；v3 统计必须排除 v2 的 `compose/evaluate/refine/run/judge` 等历史行。
- 错误包络统一 `{ code, message, retryable? }`；不要沿用 `/api/prompts` 的 `detail` 字段。
- 不改 `lib/llm/types.ts` 与 `lib/engine/schema.ts`；v3 新代码不 import v2 引擎。
- 不新增依赖；不创建 `lib/templates/` 目录（与既有 `lib/templates.ts` 冲突）。
- 界面未参与本批，所有服务端文案中文、无感叹号与 em dash。
- Phase 6 才删的模块本批只读：`/api/prompts`、`lib/db/prompts.ts`、`lib/db/runs.ts`、`lib/templates.ts`、`/api/run`、`/api/eval`。
- 每个任务结束跑 `pnpm run typecheck` 与自己的定向测试；收口时跑全量 `pnpm test`。

### Controller Rulings（与下文任务步骤冲突时以此为准）

- 记录日期筛选按 Asia/Shanghai 日历日：`from` 为当日 00:00（含），`to` 为次日 00:00（不含），不按 UTC 切日。
- 重复删除自定义模板返回 404 `TEMPLATE_NOT_FOUND`，不是 204。

## Review Focus

1. **元数据编辑不得改变列表排序**：收藏、评分、改名不应把记录顶到「最近处理」最前；PATCH 必须保留原 `updatedAt`，列表按 `updatedAt desc, id desc`。
2. **删除记录的账本匿名性**：删除记录与迭代正文，但 `LlmCall` 行保留且 `recordId/iterationId` 置空，不能级联删除。
3. **未知金额被写成 0**：当月全未知费用、预算未设置、平均费用无分母，都必须返回 `null`，UI 显示「—」。
4. **v2 账本混入 v3 统计**：历史 `compose/evaluate` 行必须被过滤，否则成本页多算。
5. **并发删除/续写**：存在 running 迭代的记录拒绝删除与续写，返回 409，不允许半途删除正在生成的记录。

- [ ] **Step 3: 实现 `listRecords` 与路由 GET**

`listRecords` 的 where：

```ts
const where: Prisma.PromptRecordWhereInput = { latestOutput: { not: '' } }
if (query.q) where.OR = [
  { title: { contains: query.q } },
  { sourceInput: { contains: query.q } },
  { latestOutput: { contains: query.q } },
]
if (query.filter === 'favorite') where.favorite = true
if (query.filter === 'rated') where.rating = { not: null }
if (query.filter === 'generate' || query.filter === 'optimize') where.mode = query.filter
if (query.targetType) where.targetType = query.targetType
if (query.from || query.to) where.updatedAt = {
  ...(query.from ? { gte: query.from } : {}),
  ...(query.to ? { lte: query.to } : {}),
}
```

`findMany({ where, orderBy: [{ updatedAt: 'desc' }, { id: 'desc' }], skip, take })` 与 `count({ where })` 在同一 `Promise.all`。列表 select 不含 `latestOutput`。

路由：`q` 去首尾空格、1..200 字符；`limit` 1..50 默认 20；`offset` ≥0 默认 0；`filter`、`targetType` 用 zod enum；`from/to` 接收 `YYYY-MM-DD` 并转 `new Date(`${value}T00:00:00.000Z`)`。非法参数 400 `INVALID_QUERY`。响应 200 `{ records, total, limit, offset }`，`Cache-Control: no-store`。

- [ ] **Step 5: 实现 `updateRecordMeta`、`deleteRecord` 与 PATCH/DELETE 路由**

`updateRecordMeta`：

```ts
const record = await prisma.promptRecord.findUnique({ where: { id: input.recordId } })
if (!record) throw new RecordNotFoundError()
const wantsRatingChange = input.rating !== undefined || input.favorite !== undefined
if (wantsRatingChange && !['completed', 'canceled'].includes(record.status)) {
  throw new RecordNotReadyError('记录还在处理中或没有可用结果，暂时不能评分或收藏。')
}
return prisma.promptRecord.update({
  where: { id: record.id },
  data: { ...changes, updatedAt: record.updatedAt }, // 保留最近处理时间
})
```

`deleteRecord`（事务）：

```ts
await prisma.$transaction(async (tx) => {
  const iterations = await tx.promptIteration.findMany({
    where: { recordId },
    select: { id: true },
  })
  await tx.llmCall.updateMany({
    where: { OR: [{ recordId }, { iterationId: { in: iterations.map((it) => it.id) } }] },
    data: { recordId: null, iterationId: null },
  })
  await tx.promptRecord.delete({ where: { id: recordId } }) // 迭代级联删除
})
```

`RecordNotFoundError` 与 `RecordNotReadyError` 在 `lib/db/records.ts` 导出。DELETE 前置检查：记录不存在 → 204；`record.status === 'running' || record.iterations.some((it) => it.status === 'running')` → 409 `ITERATION_IN_FLIGHT`。PATCH 用 zod 拒绝空对象与未知字段。
