# PromptPilot v3 Phase 5 Settings & Cost Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Replace the v2 evaluate-model settings with v3 generate/optimize model slots, add per-role temperature and max_tokens, add monthly budget editing, and switch the settings cost section to the v3 ledger with four KPIs, a 14-day trend, two tables, and 80% / 100% budget prompts.

**Architecture:** `lib/settings/store.ts` stays the single source for the settings view, writable patch, effective model params, and budget. `GET/PUT /api/settings` carries model slots, numeric params, and budget; `POST /api/settings/test` pings generate and optimize. The settings server page reads `getV3Stats()` and renders the KPI/trend/table block plus a client `BudgetSetting`; `LlmSettingsForm` switches from 评估模型 to 优化模型 and adds four numeric fields. The four v3 generation routes read `getEffectiveModelParams(role)` instead of hardcoding `maxTokens: 8192`.

**Tech Stack:** Next.js 16 App Router, React 19, TypeScript strict, Tailwind v4, Prisma 6 + SQLite, vitest 5, pnpm 10.14.0.

**Spec:** `PRODUCT.md` FR-8, FR-9, AC-12, AC-13, AC-14, AC-17, AC-26; `DESIGN.md` Settings Panels, State Matrix, Do's and Don'ts; `docs/ROADMAP-V3.md` Phase 5 (V3-50..54); `docs/ARCHITECTURE.md` §四.

## Global Constraints

- UI copy lives in the page/form modules; v3 studio copy stays in `lib/i18n/zh.ts`. No `!`, `！`, em dash (except unknown `—`), emoji, `强大`, `智能`, `一键起飞`.
- Chinese minimum 12px; no uppercase transforms; all numbers use `tabular-nums`.
- Gold is scarce: at most one primary button per screen; ≤2 glows on screen.
- Unknown cost shows `—`; unset budget shows `未设置`, never `0%`; zero calls is a known 0.
- `lib/llm/types.ts` and `lib/engine/schema.ts` stay frozen. No new dependencies.
- Keep `modelEvaluate` in the store and the settings API until Phase 6 because the v2 eval page still reads its override through `getEffectiveLlmEnv`; the v3 settings UI must not expose it.
- Secrets only in SQLite; API returns configured/hint (last four) and never plaintext.
- Tests use the isolated `data/test.db`; never read or write `data/app.db`.
- Targeted tests: `pnpm exec vitest run <path>` (not `pnpm test -- <path>`).
- Stage git adds by explicit path; never `git add -A`.

## Review Focus

- A saved budget with unknown cost must show `—`, not `0%`; an unset budget must show `未设置`.
- Clearing a numeric param must fall back to the default; clearing an optimize param must fall back to the generate param.
- Optimize params inherit generate params only when the optimize key is absent, including when the generate value itself is a setting.
- A corrupted numeric setting must not reach the provider; fall back to the valid default.
- `/settings` must render with a readable message when the database or stats query is unavailable.
- The client bundle must contain no `ARK_API_KEY`, `sk-`, or `Bearer` strings (AC-17).
- Long model IDs, `未设置`, and `—` must not overflow KPI tiles or the budget row.
- Generate and optimize may use the same model; the UI must not force different values.
