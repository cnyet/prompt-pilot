# PromptPilot v3 Phase 4 Template Library Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Replace the v2 scene-template page with the v3 template library: three content categories, style filtering, programmatic covers, `用它开始` prefill into the studio, and custom template deletion, while keeping the existing template APIs and seed data as the source of truth.

**Architecture:** Server component loads normalized template cards from SQLite; a client `TemplateLibrary` owns category/style selection, retry, and local deletion. Pure helpers in `lib/templates-v3.ts` normalize DTOs, resolve prefill, group/filter by style, and derive deterministic cover models. The studio resolves `?template=<id>` on the server through a new `getTemplate(id)`, then prefills the composer and carries `originTemplateId` on the first submit only.

**Tech Stack:** Next.js 16 App Router, React 19, TypeScript strict, Tailwind v4, Prisma 6 + SQLite, vitest 5, pnpm 10.14.0.

**Spec:** `docs/ROADMAP-V3.md` §2.6 and Phase 4 (V3-40..44); `PRODUCT.md` FR-7, AC-10, AC-11; `DESIGN.md` Template Card / cover / typography rules.

## Global Constraints

- UI copy lives only in `lib/i18n/zh.ts`; no `!`, `！`, em dash (except unknown `—`), emoji, `强大`, `智能`, `一键起飞`.
- Chinese minimum 12px; no uppercase transforms; all numbers use `tabular-nums`.
- Gold is scarce: ≤10% of a screen; ≤2 glows on screen; at most one primary button per screen.
- Covers are inline SVG generated from the template; no external image service, no gradients, no empty placeholder cards.
- Reuse `GET/POST /api/templates` and `DELETE /api/templates/[id]`; no schema migration and no new template fields.
- Frozen contracts stay frozen: do not touch `lib/llm/types.ts` or `lib/engine/schema.ts`.
- Keep the v2 `lib/templates.ts` and its v2 studio caller until Phase 6; only disconnect the v3 templates page and v3 studio from it.
- Tests use the isolated `data/test.db`; never read or write `data/app.db`.
- Targeted tests: `pnpm exec vitest run <path>` (not `pnpm test -- <path>`).
- Stage git adds by explicit path; never `git add -A`.

## Review Focus

- Invalid, missing, or array `?template=` values must render a usable studio without a crash or blank result panel.
- Database failure on the templates page must still render the page shell with a readable error and a retry action.
- Legacy custom generate templates with `exampleInput = null` must still prefill something usable; optimize templates prefill their body.
- Deleting the last card under an active style must reset the style selection, not leave a stale empty grid.
- Long custom titles, styles, and descriptions must not overflow cards; cover text truncates with an ellipsis.
- Built-in templates must never expose a delete control; the API's 409 remains the server-side guard.
- Optimize template entry must select optimize mode and attach `originTemplateId` only to the first record-producing submit.
- Seed copy must stay short, concrete, and free of banned punctuation and empty marketing words.
