# PromptPilot v3 Phase 6 Cleanup Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Remove the v2 eight-field product surface, its APIs, engine, tests, and old tables, then close out the v3 docs, E2E, and quality gates without changing v3 behavior.

**Architecture:** Five sequential batches, each independently verified and committed. Batch 1 first decouples the v3 shell from `GET /api/run`; batches 2 and 3 then delete the v2 UI, APIs, engine, and tests; batch 4 removes the remaining `modelEvaluate` contract, rewrites E2E/docs, and runs the accessibility pass; batch 5 backs up the database and deletes the ten v2-only tables. Code never depends on a table before that table is dropped.

**Tech Stack:** Next.js 16 App Router, React 19, TypeScript strict, Tailwind v4, Prisma 6 + SQLite, vitest 5, pnpm 10.14.0.

**Spec:** `docs/ROADMAP-V3.md` Phase 6 (V3-60..65); `docs/HANDOVER.md`; `docs/ARCHITECTURE.md`; `PRODUCT.md` AC-15/16/18 and the full AC regression; `DESIGN.md` State Matrix and Do's/Don'ts.

## Global Constraints

- No new dependencies. No `prisma/migrations/`; keep using `db push` + `generate`.
- `lib/llm/types.ts` stays permanently frozen. `EngineStage` keeps its existing union and `LLMProvider.structured()` stays on the interface.
- `lib/engine/schema.ts` is deleted only in Batch 3, after all v2 importers are gone. v3 production code must never import it.
- `LlmCall` is the v3 cost ledger source of truth. Never delete it; keep `recordId` / `iterationId` and the existing v2 association columns in this phase.
- `lib/llm/structured.ts` stays: `openai-compat.ts`, `mock.ts`, and `ledger.ts` still reference it, and `LLMProvider.structured()` is frozen.
- Tests use the isolated `data/test.db`; the HTTP E2E uses `data/e2e.db`; never read or write `data/app.db`. No test or E2E may run against the dev database.
- Secrets only in local SQLite or env; APIs return configured/hint only. Never print a key.
- Every commit ends with the attribution trailer `Co-Authored-By: Claude Code <noreply@anthropic.com>`.
- UI copy: no `!`, `！`, em dash (except unknown `—`), emoji, `强大`, `智能`, `一键起飞`; unknown values stay `—`, unrated stays `未评分`, unset budget stays `未设置`.
- Stage values remain `generate` / `optimize` / `repair`; v2 stages only survive as historical ledger labels.
- Each batch ends with typecheck, the full test suite, and a clean build. Record the new test baseline in the batch commit note.
- Stage git adds by explicit path; never `git add -A`.

## Review Focus

These are the failure modes a reasonable user would notice, and each is pinned to a task below:

1. The v3 shell loses model availability after `/api/run` disappears; every page shows `模型状态未知` (Batch 1 must land first).
2. Kept infrastructure is deleted as "v2 code": `LlmCall` / its v3 columns (cost ledger) or `structured.ts` / `LLMProvider.structured()` (every provider). Batch 3 and Batch 5 pin both.
3. Deleting ~387 v2 tests hides a v3 regression; each batch must run the full suite, not only targeted tests.
4. `db push --accept-data-loss` drops a table without a verified backup or while a dev server still holds the database (Batch 5 stops the server, backs up, and inspects `.tables`).
5. `/eval` or another v2 URL is still linked after deletion, producing a dead route (Batch 2 removes the `/eval` title mapping; Batch 4 scans docs and shell copy).
