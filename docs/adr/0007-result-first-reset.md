# ADR 0007：产品重置为「结果优先」

日期：2026-11-12
状态：已接受

## 背景

v2 以「八字段结构化 + 评估」为核心范式：字段编辑器、假设 chip、自动试运行、16 条诊断、基线 v0 盲评、版本链。实现与演示版完成后，独立 PM 评审与用户反馈指向同一个结论：过程展示本身成了负担。

- 目标用户（非技术业务人员、内容创作者）要的是可直接投产的提示词，不是一套要学的方法论。
- 结构化过程（字段骨架、假设 chip 墙、评估仪表盘、多阶段时间轴）占据了首屏，结果反而退居其次。
- 评估、试运行、版本树在首版没有形成可感知的价值，却贡献了最多的实现与维护成本。

## 决策

产品重置为 v3「结果优先」范式，由 `PRODUCT.md` v3 为事实源：

1. **只展示结果**：生成与优化都输出处理后的 Markdown 提示词，不展示结构化字段、假设 chip、JSON、推理过程。可切换「源码」查看原始文本。
2. **两条主路径**：生成（从零到有）与优化（从有到好），加上继续优化迭代；默认路径不超过三步。
3. **对比证明改进**：优化保留原文，diff（并排与行内）与最多 3 条改动说明是结果的一部分。
4. **完成即沉淀**：每次完成自动入库（PromptRecord / PromptIteration），收藏、评分、存为模板都是事后动作。
5. **模板三类**：文本 / 图片 / 视频，12 条内置模板加自定义模板，本产品不生成图片与视频。
6. **按需本地检查**：8 条确定性规则（R101-R108），P1 优先级，不点击时页面上没有诊断面板。
7. **成本可见**：模型调用全量落账，月度预算 80% / 100% 提示，未知值显示「—」不写 0。

导航收敛为 4 项：工作台、提示词库、模板、设置。评估整条链路（/eval、EvalTask、CriterionCheck、盲评胜率）废弃。

## 技术影响

- 数据模型从 `Prompt` / `PromptVersion` / `Run` 换为 `PromptRecord` / `PromptIteration` / `Template`；旧模型保留到 Phase 6，迁移只增不删。
- 生成 API 从结构化 JSON 字段流改为 Markdown 文本流；标题与改动说明通过 `<<<PROMPTPILOT_META>>>` 分隔符随正文一并流式产出，服务端剥离，解析失败降级为输入摘要与空说明。
- `lib/engine/schema.ts`（八字段契约）冻结至 Phase 1 新模型落地，Phase 6 删除。
- 模型角色从 generate / evaluate 改为 generate / optimize。

## 后果

- `docs/ROADMAP.md`（v2 里程碑）废弃，由 `docs/ROADMAP-V3.md`（7 阶段 16 人日）取代。
- `CONTEXT.md` 词表重写；「字段、版本、基线 v0、试运行、评估、假设 chip、建议」退出界面词汇。
- `ARCHITECTURE.md`、`HANDOVER.md`、`README.md` 按 v3 收口；两套 SSE 协议与数据模型不得并存描述。
- ADR-0003（评估判定输出）随评估链路废弃；ADR-0002（CSS 动效）、ADR-0005（cva + Radix Slot 工程模式）、ADR-0006（烛光羊皮纸材质）继续有效。
- 测试基线不追求数量：旧引擎测试随模块退役，新基线以 Phase 6 结果为准。
- 回滚：文档阶段可直接回退；代码阶段每阶段独立提交，数据库只增不删，删表前备份。
