# ADR-0002：动效只用 CSS，两类过渡加状态信号

- 状态：已采纳
- 日期：2026-11-10（2026-11-16 增补流式状态信号）

## 背景

页面"死"的观感主要来自内容出现时毫无提示：字段流式写完直接出现，面板展开瞬间到位。可选方案是引入动效库（Motion / GSAP）做编排，或用纯 CSS 过渡。

## 决定

不引入动效库。两类过渡动效：

1. **内容出现**（`rise`）：字段、列表项、空态首次渲染时 `opacity 0 → 1` 并上移 6px，时长 120ms。
2. **容器展开**（`reveal`）：导出浮层、诊断分组、折叠区，`opacity` + `translateY(-4px)`，时长 180ms。

外加两个功能性状态信号（只动 `opacity`，不参与过渡编排）：

3. **now 脉冲**（`now-pulse`）：工作台流式进行中的状态文字「正在生成」，2s 呼吸，表示「处理中」。语义由 `role="status"` 文本承担，脉冲只是第二重编码。
4. **流式输入符**（`stream-caret`）：工作台流式进行中，已生成正文末尾的金色光标，1.1s 硬闪烁（`steps`），表示「正文还在生长」。状态语义仍由顶部 status 文本承担，光标 `aria-hidden`。

硬性限制：

- 只动 `opacity` 与 `transform`，不动 `width` / `height` / `top`。
- `prefers-reduced-motion: reduce` 下时长归零，不做任何位移，信号直接显示。
- 同一屏内同类动效只出现一次，不给每个元素加不同延迟。
- 不用骨架屏与进度仪式代替结果（PRODUCT.md 反参考）。

## 影响

- 首屏不引入额外 JS，CLS 不变。
- 复杂编排（滚动触发、路径动画）在本项目内不可用；如果后续需要，再单独立项评估。

## 备选与放弃理由

- **GSAP**：能力强，但为两个 100ms 级别的过渡引入几十 KB 运行时，性价比不成立。
- **完全不做动效**：内容出现缺少空间连续性，是当前"粗糙感"的直接来源之一。
