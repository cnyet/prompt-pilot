# ADR-0003：评估判定输出，判不了就标「待人工判定」

- 状态：已采纳
- 日期：2026-11-10

## 背景

评估功能此前只有一个空态与版式示意，数据模型（`EvalTask` / `CriterionCheck`）早就建好但从未使用。落地时要回答三个问题：

1. 判定的对象是提示词文本还是模型输出？
2. 没有判定模型（没密钥 / 只有 mock）时怎么办？
3. 与基线 v0 的胜率怎么算？

## 决定

**判定输出，不判定文本。** 每条样本用目标版本的正文作为 system、样本输入作为 user 真实跑一次，判定看的是这次输出。

**判定模型独立于生成模型。** 用 `DEFAULT_EVALUATE_MODEL_CONFIG_ID` 对应的模型做评委，与生成模型分族，避免自评偏高。

**判不了就标待人工判定（`needs_review`），不猜。** 没有评委模型、或评委输出无法解析时：样本输出照常保存、任务照常落库，但判定结果为空，通过率与胜率都是 `null`。界面显示「—」并说明原因。

**胜率 = better / (better + worse)。** 平局不计入分母；一次对比都没有时为 `null`。通过率里「部分满足」按 0.5 计。

## 影响

- 没有密钥时评估仍可跑通，只是没有判定。这是可演示的降级路径，不会被误当成"评估完成"。
- 判定的可靠性取决于评委模型，当前没有做评委置信度校准；结论应视为参考而非判决。
- 一次评估最多 5 条样本：每条样本要跑目标 + 基线两次生成，再加一次判定，成本按 3 倍放大。

## 备选与放弃理由

- **用规则判定代替模型判定**：可以把"输出非空""包含标题"这类硬指标做出来，但它衡量不了"是否回应需求"，容易给出虚假的安全感。
- **无评委时按 0 分计**：会把"没判"显示成"全错"，是最糟的误导。
